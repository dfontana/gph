# gph

`gph` is a small, Kitty-native Mermaid previewer. It uses
[merman](https://github.com/Latias94/merman) for parsing, layout, SVG, and PNG
rendering, watches source files for changes, shows a live Kitty image preview, and
renders SVG, PNG, JPEG, and PDF files.

There is no custom diagram language in the CLI, manual node positioning, mouse
interaction, or browser/Node runtime. Mermaid decides all layout. The binary
also contains an experimental, rendering-independent `mml` module for a possible
future shorthand filetype.

## Install

```sh
cargo install --path .
```

The crate requires Rust 1.95 or newer. Live previews require Kitty.

## Watch with a live preview

```sh
gph watch diagram.mmd
```

Run the watcher in its own terminal pane and edit the Mermaid file with any editor.
`gph` uses native file-system notifications and debounces a burst of save events
before rerendering. The preview starts below the command's existing terminal
output and grows downward when its pane is resized; it never enters the alternate
screen. Invalid Mermaid leaves the
last valid preview visible and reports the error in the preview border. Press
`Ctrl-C` or `Ctrl-Q` to quit.

## Preview unsaved Helix buffers

In a Kitty pane at the workspace root, start the preview daemon before opening
Helix. LSP preview support is Unix-only because it uses Unix-domain sockets, and
requires a non-empty `XDG_RUNTIME_DIR`; `gph lsp` stores per-user runtime files
there. Helix must be launched from the same workspace and user session.

```sh
gph lsp
```

Then add this once to Helix's `languages.toml` (alongside `merman-lsp`):

```toml
[language-server.gph-preview]
command = "gph"
args = ["lsp-connect"]

[[language]]
name = "mermaid"
language-servers = ["merman-lsp", "gph-preview"]
```

Helix starts `gph lsp-connect` automatically for each Mermaid buffer; it bridges
Helix's standard input/output to that workspace socket. The daemon shows the
most recently changed open document and uses only the full unsaved text supplied
by LSP `didOpen` and `didChange` notifications—it never reads the buffer from
disk. Closing a buffer returns the preview to the next most recent open
document, and renders debounce briefly after the final edit. `gph` advertises
LSP full text synchronization (`openClose` and `change = 1`) only, so
`merman-lsp` remains the diagnostics provider. Quit the Kitty preview pane with
`Ctrl-Q` or `Ctrl-C`; the socket is removed and a later Helix connection reports
that `gph lsp` needs to be started again.

## Render files

```sh
gph render diagram.mmd -o diagram.svg
gph render diagram.mmd -o diagram.png
printf 'flowchart TD\nA --> B\n' | gph render - -o diagram.pdf
```

The format is inferred from the `.svg`, `.png`, `.jpg`/`.jpeg`, or `.pdf`
destination extension, or set explicitly with `--format`. Failed rendering never
writes the output. `gph export` remains an alias for `gph render`.

## Scope

- Kitty graphics protocol only; no Sixel, iTerm, or text fallback.
- The CLI accepts Mermaid source only; it has no MML filetype or DSL-conversion
  subcommand.
- Node locations are always generated by Mermaid/merman.

## Experimental MML syntax

The internal `src/mml` module is a rendering-independent, Lisp-like DSL for a
deliberately small Mermaid flowchart subset. It provides parsing plus MML ↔
Mermaid conversion without using any rendering code. MML-to-Mermaid is supported
for every valid MML graph.
Mermaid-to-MML is intentionally strict: it succeeds only for the subset MML can
represent and rejects unknown or lossy Mermaid syntax instead of silently
skipping it.

An MML document contains one graph expression:

```lisp
(graph DIRECTION STMT...)
```

| Direction | Meaning |
| --- | --- |
| `lr` | Left → Right |
| `rl` | Right → Left |
| `td` | Top → Down |
| `bt` | Bottom → Top |

### Nodes

```lisp
(ID)                        ; implicit node — usable by edges
(ID "Label")                ; labelled box
(ID "Label" SHAPE)          ; labelled node with a shape
```

A node declaration emits Mermaid only when it has a label. Nodes used only in
edges are implicit.

| Shape | Mermaid form | Appearance |
| --- | --- | --- |
| *(default)* | `id["label"]` | Rectangle |
| `round` | `id("label")` | Rounded rectangle |
| `diamond` | `id{"label"}` | Diamond |
| `stadium` | `id(["label"])` | Stadium / pill |
| `hex` | `id{{"label"}}` | Hexagon |
| `sub` | `id[["label"]]` | Subroutine |

### Edge chains

```lisp
(ARROW ID ID...)            ; chain with no label
(ARROW ID ID... "Label")    ; label applies only to the last hop
```

An edge requires at least two IDs. To keep declarations close to their use, an
edge may use an inline node declaration wherever it accepts an ID:

```lisp
(-> (login "Login" round) (check "Check" diamond))
```

| Arrow | Mermaid output | Appearance |
| --- | --- | --- |
| `->` | `-->` | Solid arrow |
| `-->` | `-.->` | Dotted arrow |
| `=>` | `==>` | Thick arrow |
| `-o` | `--o` | Circle endpoint |
| `-x` | `--x` | Cross endpoint |

### Strings and comments

Strings accept `\"`, `\\`, `\n`, and `\t` escapes. `;` starts a comment that
runs to the end of its line.

```lisp
(graph lr
  ; this whole line is ignored
  (-> start finish "done")) ; so is this suffix
```

### Example

```lisp
(graph lr
  (-> (login "Login" round) (validate "Validate Input" diamond))
  (-> validate (dashboard "Dashboard" stadium) "ok")
  (-> validate (error "Error" round) "fail")
  (--> error login "retry"))
```

This becomes:

```mermaid
flowchart LR
  login("Login")
  validate{"Validate Input"}
  login --> validate
  dashboard(["Dashboard"])
  validate -->|ok| dashboard
  error("Error")
  validate -->|fail| error
  error -.->|retry| login
```
